Detailed Description

bytes, bytearray, memoryview and str as zero-copy C++ views, and C++ bytes back as Python bytes.

Overview
Core reads bytes as std::span<const std::byte> and text as std::string_view. These argument types give a binding exactly that, with no copy, from whatever a Python caller has:
C++ argument accepts gives
snicholls::python::byte_view bytes, bytearray, memoryview, array.array, a C-contiguous NumPy array - anything with a contiguous buffer std::span<const std::byte>
snicholls::python::mutable_byte_view a writable contiguous buffer (bytearray, writable memoryview, NumPy) std::span<std::byte>
snicholls::python::text_view str (its UTF-8), and the bytes-like types above (taken as UTF-8 as they are) std::string_view

str is deliberately not a byte_view: text has no bytes until an encoding is chosen, so a caller writes s.encode(). Back to Python, to_bytes(span) / to_bytes(string_view) copy into a new bytes; a std::string or std::string_view result is a str as usual (<nanobind/stl/string.h>).

// Any bytes-like object, no copy: a core function over bytes sees a std::span<const std::byte>
m.def("fnv1a_64", [](const snicholls::python::byte_view& b) { return snicholls::fnv1a_64(b.chars()); }, "data"_a);
// Text: a str's UTF-8 (or bytes as they are), as a std::string_view
m.def("shout", [](const snicholls::python::text_view& t) { return std::string(t.view()) + "!"; }, "text"_a);
// Writable buffers, changed in place
m.def("zero", [](snicholls::python::mutable_byte_view b) {
for (std::byte& x : b.bytes())
x = std::byte{0};
}, "buffer"_a);
// Bytes back to Python
m.def("header", [](std::uint32_t length) {
const std::byte h[4] = {std::byte(length >> 24), std::byte(length >> 16), std::byte(length >> 8), std::byte(length)};
return snicholls::python::to_bytes(std::span<const std::byte>(h));
}, "length"_a);

Guarantees and contracts
  • The views hold the buffer (or the str) for their own lifetime, so the memory stays valid and, for a bytearray, its size stays fixed while a view exists (Python raises BufferError on a resize).
  • The views may be destroyed with or without the GIL: they take it to release the buffer.
  • Move-only.
Errors
An argument of another type, or a non-contiguous buffer, fails overload resolution (TypeError); a read-only buffer fails for mutable_byte_view. to_bytes throws std::bad_alloc (MemoryError).
Performance
O(1) for the views (one buffer request); to_bytes copies once.
Tests and demos

Dependencies
CMake target snicholls::core_nanobind. The buffer protocol is in the stable ABI from Python 3.11, so these work in abi3 modules.
Known issues and gotchas
  • Take the views by value or const& only in the function signature; never store one beyond the call.
  • A text_view of bytes is not checked for valid UTF-8, exactly as std::string_view would not be.
Status
Experimental, pre-1.0.
